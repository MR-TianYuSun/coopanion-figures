# 提示词更新记录（2026-11-26）

> 脱敏公开。展示「智能体为什么不给回复」的诊断与提示词修复思路。

## 一、问题

桌宠对话页只显示三种内容：使用者的话、智能体用 `pet_say` 冒出的气泡、工具调用记录。
智能体写在正文里的普通文字，使用者看不到。所以只要 `pet_say` 失败，用户看到的就是一片空白。

实际会话里出现过的失败链：

1. 使用者问「搜一下我做过的游戏」→ 智能体正确检索了知识库
2. 但随后串台调用读屏、刷视频等无关工具，造成报错
3. 想说话时把检索返回的文档 ID 当成图片句柄塞给 `pet_say` → 工具拒绝
4. 模型直接结束回合 → 对话页空白

## 二、提示词修复（三条回复铁律）

1. **使用者说话 = 必须有 `pet_say` 气泡。** 提问、命令、打字、语音都要回；只写正文就结束 = 最严重错误。唯一例外：只被拖动/戳且没有新指令。
2. **`pet_say` 失败就立即改参数重试**，最多两次；还不行就去掉图片参数只用纯文字再说一次。绝不带着失败静默结束。
3. **图片参数只认会话里 `[blob ...]` 行开头的附件句柄。** 文档 ID、文件路径、编造的 ID 都不是句柄，填了必报错。知识库图片只能描述，不能显示原图。

## 三、工具与插件边界

- 一问一工具集：查资料就「检索 → 读正文 → 汇报」，不顺手串台读屏/刷视频/刷新看板。
- 工具连续报错两次就停，把原因说出来，不调第三次。
- 插件各管各的：知识库只读、消息发送二选一、跨实例转达不替用户回复、桌宠不替用户对外发言。

## 四、关于「沉默」的规则对齐（关键）

旧提示词里同时存在「必须有气泡」和「安静也是一种回答 / 没话说就不调用 / 工具之间保持沉默」——
小模型会抓住后者，在工具跑完后静默结束。

修复：明确「沉默是过程，不是结尾」。工具之间可以不说话，但整轮结束前一定回到一次 `pet_say`；
「安静也是一种回答」只适用于被拖动/戳这类没有新指令的环境事件。

## 五、验证

用 4B 本地模型 + 完整前缀 + 真实工具消息格式测试三类场景：

| 场景 | 期望 | 实测 |
|---|---|---|
| 工具跑完后收尾 | 输出 `pet_say` 气泡 | 通过 |
| 直接问话 | 调用检索工具，不串台 | 通过 |
| 纯环境事件（被拖动） | 安静结束 | 通过 |
