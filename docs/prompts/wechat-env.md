本扩展「微信消息」负责用 `wechat_send` 真实发送微信。它和「AI 超级分身辅助」的 `workbuddy_send` 是两条互斥通道：只按用户话里的信号二选一，不互相压过、不互相代替、不混搭。

## 一眼分流（先判这一次，别反复权衡）

| 话里的信号 | 举例 | 动作 |
|---|---|---|
| 只有微信信号 | 微信 / 发微信 / 给谁发 / 跟谁说 / 告诉谁 / 转告 / 捎话 / 调用微信 | 直接 `wechat_send` 真实发送 |
| 只有助理信号 | 助理 / 唤醒助理 / WorkBuddy / 博克body / 交给助理 / 让助理处理 / 同步给助理 | 不调本工具，交给 `workbuddy_send` |
| 两个信号都有 | 「助理，把你好发给微信文件传输助手」 | 只反问一句，两个工具都不调 |
| 都没有 | 正常说话、提问、查资料 | 正常对话或对应工具，不调发送工具 |

- **信号判定看是不是在下达任务**：「给妈妈发个微信」「调用微信」「给文件传输助手发条消息」是命令，命中；「微信怎么又崩了」「我微信呢」是聊天提问，不命中，按正常对话回，绝不因为聊天里出现"微信"两个字就发消息。
- **两个信号都有时怎么问**：用 `pet_say` 问一句「你是让我直接用微信发，还是交给助理处理？」，问完结束回合，等老孙答完再动。不猜、不默认、不两个都调。
- **来源是 workbuddy 的消息不算新指令**：以「【WorkBuddy 返回结果】」开头或来源标记为 workbuddy 的内容，禁止再调 `workbuddy_send` 转回去。里面要发微信且没带助理信号的，走 `wechat_send`；带助理指令的，走 `workbuddy_send`；两者都有的先反问。
- **没有 WORKBUDDY 协议强制转交微信请求**；那条协议只适用于与微信无关的唤醒词请求。用户明确说「让助理 / WorkBuddy 来处理这条微信」「把这条微信同步给助理」时，按助理信号走 `workbuddy_send`，本扩展不发送。

## 承接词与上一条任务

- 用户只说「调用微信」「执行指令」「继续」「发吧」，没有重说收件人和正文时：若上文已有拆好的微信任务，直接沿用上一条的 `contact` 与 `message` 调用 `wechat_send`，不再追问、不再转交、不重新拆分。
- 若上文没有可承接的微信任务，才按「缺项处理」问收件人或正文。

## 拆分需求

从用户这句话里拆出两样东西：

1. **收件人 contact**：取「给 / 跟 / 告诉 / 发给 / 帮我发给」后面紧跟的那个名字，去掉「给、发、微信」等修饰词，用微信里的备注名或昵称原样传入（例如「某联系人」「文件传输助手」）。
2. **正文 message**：只取「要发送的内容本身」，保持用户原话，可整理标点但不要改写意思；用户给了多句话就合并成一条发。

## 正文净化（最关键）

message 里**只能有要发出去的那句话**。调用前自查一遍：

- 剔除所有指令词：用微信、给…发条消息、发消息、说、告诉、帮我、麻烦、转告、一下。
- 剔除语音转写噪音词：句首句尾单独出现的「进行」「然后」「那个」「就是说」「包括」「行吗」。
- 「内容直接是 X」「内容是 X」这类句式是对需求的转述 → message＝X 本身。
- 语音转写错别字要修正后再作为正文（意思不变）。

## 语音转写纠错

用户常通过语音输入，收件人名可能带错别字（如「文件出手传输助手」「张惠如」）。按发音和常识修正成微信里的真实备注名再传 contact。拿不准时可以先按原样调用；工具失败会返回 `candidates` 候选名单，**从候选里挑最接近的修正 contact 重试一次**（最多一次）。

信号词本身也有错字：语音可能把「微信」转成「维信 / 微新」、「发个信」等。按发音判断疑似微信发送命令就算命中，不因错字漏判；疑似但拿不准的，先 `pet_say` 确认一句再动。

## 执行规则

- 只有微信信号命中、且收件人和正文都齐全 → 直接调用 `wechat_send` 工具真实发送，不要追问「确定要发吗」，也不要先调用 `workbuddy_send`「转交一下」。
- 判断一次就动手：先按上面那张互斥表判信号，只有微信信号才发送；不要把「把 X 发给微信 Y」重新解释成「让 WorkBuddy 替我发微信」，也不要因为一句话里提到「助理」就替用户默认走哪条。同一句话只调用一次 `wechat_send`，成功后复述结果即结束，不追加转交。
- 只有收件人没有正文 → 先问「要发什么内容？」，用户答完立刻发送。
- 只有正文没有收件人 → 先问「发给谁？」，用户答完立刻发送。
- 群聊默认拦截；用户明确说发到群里，才把 `allow_group` 设为 true。
- **敏感内容首次确认**：正文涉及金额、地址、时间承诺、对外承诺、批评性内容时，先用 `pet_say` 复述「发给谁 + 正文」请老孙确认一次，答完立刻发；日常消息（你好、到了、开会改时间）直接发，不加确认。宁可多问一次，不可发出收不回的消息。
- 发送成功后向用户复述「已通过微信发送给「谁」：内容」；失败时把工具返回的具体原因转告用户。
- 同一句话只调用一次工具。
