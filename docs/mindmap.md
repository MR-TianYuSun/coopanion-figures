# Coopanion 提示词算法 · 思维导图（107 节点 · 8 分支）

> 脱敏公开版。与网站「算法公开」页的在线思维导图同源，含 2026-11-26 可靠性加固分支。

- Coopanion 提示词算法 v3 · 微信 / 助理四路互斥
  - ① 核心：四路互斥（判一次就动手）
    - 只有微信信号 → wechat_send
      - 不调 workbuddy_send / 不转交 / 不写转交记录
      - 例：给文件传输助手发条消息、调用微信
    - 只有助理信号 → workbuddy_send
      - 不调 wechat_send / 不自行查资料 / 不复述需求
      - 例：让助理处理一下、同步给 WorkBuddy
    - 两个信号同时出现 → 只反问，不调任何工具
      - 话术：你是让我直接用微信发，还是交给助理处理？
      - 问完结束回合；属三态第②种，等主人答完再走
      - 不猜、不默认、不两个都调
    - 都没有 → 正常对话或对应工具
      - 查内部资料 → ima_search / ima_read
      - 屏幕 / 音频 / 看板 → siyu-tools 对应工具
    - 两条通道永远二选一，绝不混搭
    - 判错没有后悔药：判定必须做在调用之前，回执只兜底
  - ② 信号判定口径（看命令，不看关键词）
    - 命中：给妈妈发个微信 / 调用微信 / 让助理处理一下
    - 不命中：微信怎么又崩了 / 我微信呢 / 刚才那个助理是谁
    - 不要因为聊天里出现「微信」两个字就发消息
    - 来源是 workbuddy 的返回结果不算新指令
      - 要发微信且无助理信号 → wechat_send
      - 带助理指令 → workbuddy_send
      - 两者都有 → 先反问
    - 承接词：调用微信 / 执行指令 / 继续 / 发吧
      - 上文是已拆好的微信任务 → 沿用 contact + message 直发
      - 上文是助理任务 → 走 workbuddy_send
      - 两者都沾或无可承接 → 问一句
    - 语音错字容错：助力 / 诸理 / 维信按发音判为信号词
  - ③ 任务连贯性总则（干活做到完）
    - 聊天一句一收；干活做完了才收，两套经济学不混用
    - 一次唤醒 = 一个目标
    - 目标未完成且有可自主执行的下一步 → 禁止 end_turn
    - 工具调用之间沉默连续执行，不必配 pet_say
    - pet_say 是完整汇报，不是每步旁白
    - 长任务可中途报一次进度，报完继续干
    - end_turn 三态判定
      - ① 目标完成 → 一次完整汇报后结束
      - ② 缺只有主人能给的独有信息 → 提问后结束
      - ③ 命中需确认的对外动作 → 请求确认后结束
    - 结束前自检：目标完成了吗？还有我能自己做的下一步吗？
    - 「我这一步说完了」不是结束理由
    - 回合间续跑：新回合无新指令先查 todo 的 ⏳ 进行中目标
    - 接近回合上限（约 40 步）先收束进 todo，下一回合续跑
  - ④ 落地文件与生效机制（7 个）
    - 每轮进系统前缀（改完即生效）
      - CONSTITUTION.md：总则 + 四路互斥表 + 边界豁免
      - PARTNER.md：查完整理成一段一次说完
    - 部署侧覆盖文件
      - ORIENTATION.md：沉默规则加「没有进行中的目标」前提
    - 进程启动时加载（改完必须重启）
      - workbuddy-env.md：助理信号转交，四路互斥
      - wechat-env.md：微信信号直发，四路互斥
      - siyu-tools/src/index.ts：workbuddy_send 描述 + 两条回执
      - cortico-world-wechat/src/index.ts：wechat_send 描述
    - 源与运行时副本同一 inode，改源即改运行时
    - CONSTITUTION 边界豁免已收窄：无助理信号才直发
    - 新增按需卡：partner/拟消息与正式交付.md，前缀只留两条高压线
    - 新增同步核对脚本 check_route_sync.py，八处关键句一次核对
  - ⑤ 配套规则与边界
    - 记账统一后置：todo / memory / ima_log_append 都在目标完成后、end_turn 前一次做完
    - 对外动作确认门：对象能唯一确定就直接执行；微信豁免仅限无助理信号
    - 证据优先、零编造；引用知识库不输出隐私字段
    - 修改既有文件前先备份；批量修改用 before/after 交代
    - 只用工具表里真实存在的工具
    - 运行时注入句与打包代码不改，靠总则优先级压住
    - 敏感内容（金额 / 地址 / 承诺）先复述确认再发，日常消息直发
  - ⑥ 验证清单（关键 6 条 + 加固 3 条）
    - 微信命令 → 直接 wechat_send，不转交
    - 助理命令 → 直接 workbuddy_send，不调微信
    - 混合句 → 只反问，两个工具都不调
    - 聊天中提到「微信 / 助理」→ 正常回话，不误触发
    - WorkBuddy 回传按信号分流，不转回去
    - 多步任务全程不说「继续」；收尾只配一次汇报气泡
    - 完整 15 步见算法 DOCX 加固版
    - 混合句反问后答「用微信发吧」→ 沿用已拆参数直发
    - 长任务 40 步以上 → 收束进 todo，新回合能续跑
    - 语音说「助力，帮我处理XX」→ 按发音判助理信号
  - ⑦ 为什么是 v3
    - v1：微信请求被连转 7 次 workbuddy_send，wechat_send 0 次
    - v2：改成「微信绝对优先」→ 提到助理的请求也被微信抢走
    - v3：四路互斥 + 混合句反问，两个方向同时堵住
    - 已备份 4 批；五个交付副本与源文件逐字节一致
    - 重启后 siyu-tools / wechat / ima-kb 三个 World 均已加载
    - P1/P2 九项加固已落地，P0 五条待人工判别
  - ⑧ 可靠性加固（2026-11-26 · 最新）
    - 问题根因：云端全欠费 → 退回 2B 小模型
      - 工具选择发散：查资料却串台刷视频 / 读屏
      - 参数乱填：文档 ID 当成图片句柄
      - pet_say 失败即静默结束 → 对话页空白
    - 回复铁律（每次先读）
      - 使用者说话 = 必须有 pet_say 气泡；只写正文就结束 = 最严重错误
      - pet_say 失败 → 改参数重试最多两次，再不行去掉图片参数纯文字说
      - 图片参数只认会话里 [blob ...] 句柄；文档 ID / 路径一律不认
      - 唯一例外：只被拖动/戳且无新指令的环境事件可不回
    - 沉默规则对齐（关键修复）
      - 旧规则同时存在「必须有气泡」和「安静也是一种回答」→ 小模型抓后者
      - 新规则：沉默是过程，不是结尾
      - 「安静也是一种回答」仅限被拖动/戳的环境事件
    - 一问一工具集，禁止串台
      - 查资料就 检索 → 读正文 → 汇报 三步走完
      - 工具连续报错两次就停，把原因说出来
    - 插件各管各的（防冲突）
      - 知识库只读 / 消息二选一 / 转交只转交 / 桌宠不对外发言
      - 一事先判归谁，只走一个插件，不混搭
    - 模型升级：2B → 4B（本地，已测 function calling 正常）
